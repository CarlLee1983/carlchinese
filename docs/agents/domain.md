# Domain Docs

## Layout and Reading Order

This repository uses a single-context layout.

Before exploring domain behavior, read root `CONTEXT.md`, the existing
authoritative glossary, and relevant decisions in `docs/adr/`.
Use CONTEXT.md wherever an engineering skill asks for GLOSSARY.md.

For content or reading-page work, also read:
- `docs/content-map.md`
- `docs/content-guide.md`
- `docs/content-schema.md`
- `docs/reading-page-handoff.md`

## Consumer Rules

Use the glossary's terms and respect explicitly discouraged synonyms.
Keep terminology in CONTEXT.md rather than creating a duplicate glossary.

Surface conflicts with accepted ADRs explicitly, including the reason
a decision may need reconsideration.

If an optional domain document is absent, proceed without manufacturing
a placeholder. Record genuine terminology or decision gaps when relevant.

Public deployment requires separate authorization and completion of
the outstanding content checks documented in the handoff.
